# Analog Devices Reference Alignment and Scope

Source: `references/analog_devices/analog_devices_testing_data_converters.pdf`, Chapter 5, particularly Section 5.2, Testing ADCs. The user requires this manual to take precedence when applicable methodological conventions differ. PDF pages below are numbered from 1; references such as 5.31 refer to printed page numbers.

The supplied chapter is from Analog Devices (ADI). This technical chapter contains multiple test methods and practical recommendations. It is not a checklist requiring every test in every experiment. The current implementation aligns the ideal SAR model and coherent single-tone FFT only. Unimplemented capabilities are explicitly identified; full manual coverage is not claimed.

## Retained methods and project choices

- Printed 5.63-5.64 (PDF 65-66) permits coherent and noncoherent testing. This project uses coherent sampling without an additional window and integrates one bin per fundamental or harmonic. The noncoherent leakage widths of +/-10 or +/-25 bins, +/-3 harmonic bins, and six DC bins do not apply to this mode.
- The five-average software default in Figure 5.65 is useful for records containing random variation. This model has no random source, so repeated identical records provide no additional information. The current run uses one deterministic record and does not claim five independent measurements. Future random-noise or measured-data processing should average linear powers, not dB values; reduced noise-floor variation must not be described as a lower mean noise floor.
- The 12-bit resolution, 1 MS/s sample rate, 0-1 V range, -1 dBFS input, and 997 cycles are project parameters, not uniquely mandated device specifications. Changing the record length changed the default input frequency from about 15.213 kHz to 60.852 kHz according to the exact coherent relationship.
- Implementation 3.0.2 also permits a 0 dBFS full-scale sine, selected through amplitudeDbfs in main.m; -1 dBFS remains the default. ADI Equation 5.22 (printed 5.50 / PDF 52) discusses ENOB from full-scale SINAD, while Equation 5.23 (printed 5.51 / PDF 53) includes the below-full-scale correction. The existing analyzer retains both ENOB values and applies its measured-fundamental correction without a special full-scale branch. Exact upper-endpoint samples remain in FFT, including the existing maximum-code saturation behavior. One full-scale sine test characterizes its specified amplitude and frequency, not all dynamic conditions or static code linearity.
- Implementation 2.4.0 schedules acquisition and individual bit decisions explicitly. The default 200 ns acquisition duration and 25 ns per bit are ideal project assumptions, not values prescribed by this chapter or a particular chip. They leave the coherent sample times, transfer convention, and FFT definitions unchanged; no physical settling or comparator delay law is modeled.
- SNR excludes DC, the fundamental, and selected harmonics. SINAD excludes DC and the fundamental but includes distortion. A summary sentence on PDF 65 and some subsequent sentences on PDF 66 contain omissions or crossed metric names. The implementation follows the explicit component definitions, cross-checked against Figures 5.67 and 5.68, and does not count the signal itself as noise.
- Equation 5.28 uses a peak-relative spectral reference, while Figure 5.64 also presents dBFS. This project retains an explicit full-scale sine power reference. Harmonic levels, THD, and SFDR use their documented dBc definitions; the references are not mixed.
- Implementation 3.0.1 reports the analysis band, frequency-bin width, rectangular-window equivalent noise bandwidth, and selected harmonic range. For this window, both widths are Fs/M in hertz. Reporting noise bandwidth is also supported by Understanding Delta-Sigma Data Converters, second edition, Appendix A, printed 489-491 / PDF 495-497, supplied in references/about fft. The displayed spectrum remains power per bin in dBFS, not power spectral density in dBFS/Hz.
- The user selected a minimal reporting update after reviewing the additional FFT references. Toolbox adoption and a toolbox comparison are deferred. FFT normalization, coherent rectangular-window processing, default parameters and metric definitions remain unchanged. No additional time-domain plot, noncoherent mode, external-data import or smoothing is added in this update. Figure 5.68 includes a time-domain display; that display remains outside the current automatic report.
- The half-LSB shift in Figure 5.29 defines an ideal transfer convention. This testing chapter does not specify the physical capacitor topology or a circuit for that shift. Implementation 3.0.0 selects a single-ended binary-weighted charge-redistribution array with a unit dummy capacitor. It explicitly assumes an ideal comparator-reference voltage source at the sampling top-plate clamp plus half a nominal LSB; this intentional bias realizes the selected transfer convention and is not a modeled random comparator offset. With zero shift, the same array has integer-LSB transitions.
- The capacitor switching and charge-conservation principle is described in the DAC section and Figure 3 of Analog Devices, [Successive-Approximation-Registers: SAR and Flash ADCs](https://www.analog.com/en/resources/technical-articles/successive-approximation-registers-sar-and-flash-adcs.html). The added comparator-reference bias, 10 fF nominal unit capacitance, and 0 V sampling top-plate clamp are project assumptions, not requirements from that article or the supplied testing chapter. Ideal references may support the internal node excursion; supply rails, comparator common-mode limits, parasitics, and transistor behavior are not modeled.

## Future work: manual entry points, not yet implemented

| Work | Manual location | Key constraints and current status |
|---|---|---|
| Static transitions, offset/gain, DNL/INL | Printed 5.28-5.31 / PDF 30-33 | Use code transitions; code-center lines can hide INL. Only ideal transitions have been checked so far. |
| Triangle-wave code density | Printed 5.38-5.41 / PDF 40-43; Equation 5.15 | Slightly overdrive, exclude endpoint codes, consider hits per code, and avoid sampling-frequency subharmonics. A histogram alone does not prove monotonicity. |
| Sine-wave code density | Printed 5.42-5.44 / PDF 44-46; Equations 5.16-5.18 | Use the nonuniform probability distribution and cover endpoint codes. The current -1 dBFS FFT stimulus cannot simply be reused. |
| Noncoherent FFT | Printed 5.55-5.59 and 5.63-5.64 / PDF 57-61 and 65-66 | Requires windowing and signal, harmonic, and DC leakage integration. Multiplying by a window is insufficient to reuse the single-bin analyzer. |
| Measured input, clock, and noise | Printed 5.60 and 5.66 onward / PDF 62 and 68 onward | Low-jitter clocks, low-distortion sources, filtering, supplies, grounding, and layout matter. Ideal simulation sources do not validate a laboratory setup. |

| Two-tone, BER, and video tests | Figure 5.69 and later dedicated sections | These require separate experiments and are not validated by the current single-tone FFT. |

## Versioning and migration

Implementation 3.0.1 adds reporting annotations and analysisSettings to the spectrum and exported summary. Configuration schemaVersion 3 and exportFormatVersion 3 are retained because existing fields and numerical meanings are unchanged; the settings are additive metadata.

The configuration schemaVersion changed from 1 to 2 for transfer and measurement conventions, and to 3 for the physical capacitor array and explicit reference-bias assumptions in implementation 3.0.0. Schema 3 keeps the default ideal half-LSB transfer and FFT conventions; it does not make old configuration structures sufficient to specify the new circuit. Replay historical snapshots or deliberately supply the new settings. Recompute comparatorReferenceShiftVolts when changing resolution or reference span if retaining the half-LSB convention. Preserve historical data and distinguish mathematical equivalence from bit-exact floating-point equality. Each summary.json and run.mat records parameters, MATLAB version, and the ADI reference. Current results and verification evidence are documented in the MATLAB subproject's documentation/VERIFIED_SIMULATION_RESULTS.md.
